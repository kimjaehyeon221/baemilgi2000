# UI 개발·배포 절차

UI 변경은 아래 순서를 지킨다.

1. `main`의 최신 코드를 로컬 검증 작업공간에 동기화한다.
2. Expo Web을 iPhone 크기(393 × 852)로 실행한다.
3. 온보딩, 홈, 퀘스트, 기록, 도전, 훈련 화면을 직접 캡처한다.
4. 화면 잘림, Safe Area, 터치 영역, 정보 밀도, 주요 행동의 우선순위를 검토한다.
5. TypeScript 검사를 통과시킨다.
6. 관련 파일을 하나의 커밋으로 묶어 `main`에 반영한다.
7. production OTA가 성공한 것을 확인한다.

## 배포 원칙

- 검증 전에는 production OTA를 만들지 않는다.
- UI와 스타일 파일을 서로 다른 배포로 나누지 않는다.
- `app.json`, Expo SDK, 네이티브 라이브러리, 권한 또는 아이콘 변경은 새 TestFlight 빌드로 처리한다.
- JavaScript, 문구와 일반 스타일 변경만 OTA로 보낸다.
- 기존 앱을 삭제하지 않는다. TestFlight 업데이트와 OTA 재실행으로 갱신한다.
